# 타자 연습 문장 목록 조회 API 연결

## 사용자 프롬프트

문장 목록 조회, 추가, 수정, 삭제 API 연결을 각각 별도 커밋으로 나눈다.

## 기존 상태

- 문장 설정 모달은 페이지 UI 폴더에 있었고, 파일 내부의 고정된 Mock 배열을 목록으로 표시했다.
- 서버에서 사용하는 문장 식별자, 문제 유형, 본문을 표현하는 공용 타입이 없었다.
- 문장이 많아질 때 목록 영역을 독립적으로 스크롤할 수 없었다.

## 작업 내용

- 문장 데이터를 표현하는 `TypingProblem` 타입을 추가했다.
- `/admin/typing/problems`를 호출하는 `getProblems` 조회 함수를 entities 레이어에 추가했다.
- 문장 설정 모달을 features 레이어로 이동하고 배럴 export를 추가했다.
- 모달이 열리면 문장 목록을 조회하여 최신 식별자부터 표시하도록 변경했다.
- 서버의 `DAILY`, `JAVASCRIPT`, `JAVA` 값을 화면의 일상, JS, Java 라벨로 변환했다.
- 목록 높이와 세로 스크롤을 지정해 항목 수가 늘어나도 모달 내부에서 확인할 수 있게 했다.

## 결과

- 문장 설정 화면이 고정된 예시 대신 서버의 실제 문장 목록을 표시한다.
- 각 항목은 서버 식별자를 React key와 후속 수정·삭제 대상 식별에 사용할 수 있다.
- 문장이 많아져도 모달 전체 레이아웃을 벗어나지 않고 목록 영역 안에서 탐색할 수 있다.
