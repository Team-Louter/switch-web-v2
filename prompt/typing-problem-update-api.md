# 타자 연습 문장 수정 API 연결

## 사용자 프롬프트

문장 목록 조회, 추가, 수정, 삭제 API 연결을 각각 별도 커밋으로 나눈다.

## 기존 상태

- 목록에서 수정 버튼을 누르면 선택한 문장의 유형과 내용은 편집기에 표시되었지만, 제출 결과가 서버에 반영되지 않았다.
- 추가와 수정 요청을 구분할 수 있는 문장 식별자는 편집 상태에만 존재하고 API 호출에 사용되지 않았다.

## 작업 내용

- `/admin/typing/problems/{problemId}`에 변경된 문제 유형과 내용을 전송하는 `updateProblem` 함수를 별도 파일에 추가했다.
- 편집 대상이 있으면 생성 요청 대신 대상의 `problemId`를 사용해 수정 요청을 보내도록 제출 로직을 분기했다.
- 수정 요청 중에는 제출 버튼을 비활성화하고, 성공 시 목록으로 돌아가 갱신된 내용을 다시 확인하도록 했다.
- 수정 실패 시 편집 중인 값을 유지하여 사용자가 다시 제출할 수 있게 했다.

## 결과

- 목록에서 선택한 문장의 카테고리, 개발 언어 또는 본문을 서버 데이터에 반영할 수 있다.
- 추가와 수정 API가 파일과 실행 분기에서 구분되어 각 동작의 책임이 명확해졌다.
- 수정 요청이 완료된 뒤 최신 목록이 표시되어 변경 결과를 바로 확인할 수 있다.
